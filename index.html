Engineering Case Studies

How I approached complex AI and automation problems — from business problem to production solution.

01
Building a Full AI Function from Scratch as the Only Technical Person
Situation

Joined a DHA-licensed healthcare group with no existing AI capability, no technical team, and a founder with a broad ambition to "use AI for sales and operations" — no spec, no budget baseline, no prior tooling.

Approach

Mapped the highest-friction manual workflows first: inbound lead handling, follow-up drafting, call notes, and proposals. Prioritised by impact-to-effort ratio. Started with the WhatsApp AI assistant and CRM copilot — the two workflows that consumed the most staff time — before expanding to call summarisation and proposals.

Execution

Built each system end-to-end: prompt architecture, API integration, CRM write-back, error handling, and staff playbooks. Ran user acceptance testing with real staff before each launch. Iterated on prompts based on live usage — not just happy-path demos.

6 AI systems shipped and running in production. Staff operate them independently. Speed-to-lead, proposal turnaround, and call logging all fully automated.

02
Making AI Outputs Testable — Validation Framework for Non-Deterministic Systems
Problem

The AI scheduling engine at IFS produced different outputs every run. Standard test assertions failed constantly — not because the system was wrong, but because exact-value testing doesn't work on non-deterministic AI. The team had no reliable way to know if a change broke something.

Investigation

Studied the domain constraints the AI had to satisfy regardless of its specific output — resource capacity limits, task dependency ordering, cost ceilings, SLA windows. These were invariants: properties that must always hold true even when the output varies.

Solution

Built a validation framework using rule-based assertions, invariant checks, BERTScore / embedding similarity for LLM outputs, and probabilistic tolerances. Outputs are validated against business constraints — not expected values — making the suite stable regardless of non-determinism.

Adopted as the R&D team's standard methodology for all AI features. Near-zero AI-related production escapes across 90+ sprints on a live production platform.

03
Automation Framework That Cut Execution Time 60% and Lifted Coverage to 78%
Problem

The IFS platform had 30% automated coverage and slow, fragile test runs. Manual testing was the primary quality gate — unsustainable across 90+ sprints on a fast-moving AI platform. The team had no confidence in releases without days of manual regression.

Approach

Architected a Python framework (Playwright + Selenium, Pytest, Page Object Model) spanning UI, API, and database layers. Designed coverage tiers: fast smoke suite for every commit, full regression nightly, targeted suite for feature areas under active development.

Execution

Wired the framework into Jenkins CI/CD with Allure dashboards and Slack / email alerts. Added the LLM validation layer for AI-specific outputs. Maintained and extended the suite across 3 years of platform growth as sole automation owner.

Coverage: 30% → 78%. Execution time cut 60%. Feedback within 2 hours of every commit. Manual regression eliminated as the primary gate.

04
Prompt Engineering for a Healthcare AI Agent — Safety, Tone & Reliable Escalation
Problem

Early versions of the WhatsApp AI assistant occasionally gave unhelpful responses to sensitive medical queries, failed to escalate when it should have, and drifted off-topic when patients asked complex questions. Not acceptable in a healthcare context.

Investigation

Logged and categorised 200+ real conversations to identify failure patterns: missed escalation triggers, over-confident responses, topic drift, and tone inconsistencies. Created an eval set of known failure cases to test against.

Resolution

Rebuilt the prompt architecture with explicit escalation rules, topic guardrails, tone guidelines, and uncertainty handling. Added a classification layer before the main response to route sensitive query types. Ran eval set after every prompt change to track regression.

Escalation reliability improved significantly. Agent now handles sensitive queries with appropriate caution and routes edge cases correctly without human intervention.

05
Driving Real AI Adoption — Getting Non-Technical Staff to Use AI Tools Daily
Problem

After shipping the CRM copilot and proposal generator, adoption stalled. Staff found the tools powerful but intimidating — they didn't know how to prompt them effectively and reverted to manual work whenever outputs felt "off."

Investigation

Spent a week shadowing the team's actual workflows. Found that the gap wasn't the tools — it was the interface between human intent and LLM input. Staff didn't know how to frame requests, and outputs varied too much without structured prompts.

Resolution

Built structured prompt libraries — one per tool, with real examples from their workflows. Wrote lightweight playbooks covering the 5–6 scenarios each role actually uses. Ran 1:1 sessions until each staff member could get good results independently.

All 6 AI tools now used daily without engineering support. Adoption is sustained behaviour, not a demo. Staff report saving 1–2 hours per day on tasks they previously did manually.

06
End-to-End Call Summarisation Pipeline — Transcription to Structured CRM in Minutes
Problem

Sales and care coordination calls were being logged inconsistently or not at all — staff wrote brief manual notes that missed action items, patient concerns, and follow-up commitments. Critical information was being lost between calls and CRM entries.

Design

Mapped the information that actually mattered from a call: patient name, concern, service discussed, next action, urgency level, and assigned owner. Designed the LLM extraction prompt around these fields specifically — not generic summarisation.

Build

Built a pipeline: call recording → Whisper transcription → Claude extraction prompt → structured JSON → Pronnel CRM API write-back. Added validation on the JSON output before CRM write to prevent malformed entries. Triggered automatically via webhook on call completion.

Manual call note-taking eliminated. Every call logged to CRM within minutes. Action items and follow-ups captured consistently across all staff.
